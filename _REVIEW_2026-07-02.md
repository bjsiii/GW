# CFITOOLS Foundation Review — 2026-07-02

Independent review of the Wills Builder foundation (BW + CS) ahead of FR/CL build-out.
Scope per Ben: verify the underlying product is sound, the math makes sense, and it's tested.
Ground truth = current code + git history (the May reference doc is a stale snapshot).

**Verdict: the foundation is sound.** The calculation core is correct (every hand-computed
case matched), state flow is single-source-of-truth, and the four real bugs found were all
output-integrity issues — now fixed and locked down by tests. FR/CL can safely inherit this
architecture.

---

## 1. Test harness (new)

`_tests/` — 41 automated checks, **no Node required** (fits the zero-tooling philosophy):

```
python _tests/run.py            # serves repo, drives headless Edge, prints pass/fail
python _tests/run.py --verbose  # every PASS line too
```

- Loads the **same vendor + app files in the same order** as the shipped bundle.
- Unit-tests the pure logic (`deriveBWBullets`, `deriveCSBullets`, `calcCSFloorSF`,
  `buildOverview`, `buildCoverMoveDocXml`, `buildDocxBlob`, `parseAddressTown`, `formatPhone`)
  which is now exposed on `window` for testability.
- Integration tests drive the real rendered `<App/>`: product toggle → wall entry → output
  materials; Cover & Move survives tab switches; New Customer clears everything.
- Smoke-boots the packed `index.html` headless (catches bundle/loader breakage).
- Auto-runs `_bundle.py extract` on a fresh clone (since `_src/` is gitignored).

**Run this after every change, before every pack/commit.** When FR/CL are built, add their
derive functions to the same suite.

## 3. Bugs found & fixed this review (commit 84ce9da)

1. **Cover & Move omitted CS Wall liner — always.** The overview gated it on a dead
   `items.liner` checkbox no UI sets (leftover from the pre-WL-walls design), while the
   FINAL view gates on computed SF. The foreman's .docx was missing a real material.
   Now both gate on `wlSF > 0`.
2. **New Customer didn't clear Cover & Move.** The June 30 fix that keeps CoverMove mounted
   across tab switches (correct) silently broke the global reset: site notes, hazards,
   payment method etc. carried from one customer into the next customer's .docx. Now keyed
   by `resetKey` — tab switches still preserve, New Customer clears.
3. **DOCX line breaks were schema-invalid OOXML** (`<w:br/>` between runs instead of inside
   one). Word tolerated it; stricter consumers (validators, some converters) may not. Fixed.
4. **Town-named streets hijacked the assessor button** on comma-less addresses
   ("10 Providence St Worcester MA" → opened Providence RI). End-of-address match now runs
   before the longest-substring scan.
5. *(minor)* Inspection-ports rail badge disagreed with the output when "0" was typed.

## 5. Notes for the FR/CL build-out

- Follow the CS pattern: one `INITIAL_*` state object, one pure `derive*Bullets(data)`
  returning `{ contractor, customer, ...totals }`, UI reads only derived values. That purity
  is what made this foundation testable — keep it.
- Add each new derive function to `window` and give it a unit block in `_tests/tests.jsx`
  with hand-computed expectations *before* wiring the UI.
- `copyAllWills` (App.jsx) and `buildOverview` (CoverMove.jsx) both need a new section per
  product — they are the two easy-to-forget integration points (that's exactly where the CS
  wall-liner bug hid).
